High-Level Design (HLD)
System overview
The system is a single-page React application (client) that communicates with an Express REST API (api) using JSON over HTTP. The API persists data in SQLite via Sequelize models. Enhancements introduce server-side query capabilities on the course catalog endpoint (search, owner filter, sort, pagination) and a new Favorites capability implemented as a join table between Users and Courses with authenticated endpoints. The UI keeps catalog state (q, ownerId, sort, page, pageSize) in the URL query string for shareable and reload-safe navigation.

Primary user flows
Catalog search + pagination: User enters keyword q on /courses; client updates URL, calls GET /api/courses?q=&page=&pageSize=; API returns items plus pagination meta; UI renders results and enables/disables Prev/Next accordingly, showing empty-state when no matches.

Catalog owner filter + sorting: User selects ownerId and sort; client updates URL query, calls GET /api/courses?ownerId=&sort=; API validates sort and returns ordered, filtered results; user can combine with keyword search and pagination.

Favorite toggle + My Favorites: Authenticated user toggles Favorite on course detail; client calls POST/DELETE /api/courses/:id/favorite; UI updates without refresh. User navigates to /favorites to list favorites via GET /api/users/me/favorites. Deleting a course cascades to favorites to avoid orphans.

Low-Level Design (LLD)
Database Design
Existing models
User (api/models/user.js)
    

id: INTEGER PK autoincrement

firstName: STRING not null

lastName: STRING not null

emailAddress: STRING not null unique

password: STRING not null (hashed via validatePassword validator)

Associations: User.hasMany(Course) via foreignKey fieldName 'userId'

Course (api/models/course.js)
    

id: INTEGER PK autoincrement

title: STRING not null

description: TEXT not null

estimatedTime: STRING nullable

materialsNeeded: STRING nullable

Associations: Course.belongsTo(User) via foreignKey fieldName 'userid' (note casing mismatch)

Schema changes
Add Favorites join table model (Favorite) with columns: id (PK), userId (FK -> Users.id), courseId (FK -> Courses.id), createdAt, updatedAt; enforce unique constraint on (userId, courseId); FK cascade on delete for Course and User.

Add DB index on Courses.userId and optionally on Courses.title for faster filtering/sorting.

Align Course foreign key naming to 'userId' consistently (optional corrective migration).

Seed update strategy
Seed at least 3 users and > 25 courses to validate pagination.

Ensure multiple courses per user to validate owner filter.

Seed at least one user with 5+ favorites across different owners.

Frontend Architecture
Component structure
Catalog page: Courses (container), CatalogToolbar (new), PaginationControls (new), EmptyState (new), existing course cards list.

Detail page: CourseDetail (existing), FavoriteToggle (new), existing ownership actions.

Favorites page: MyFavorites (new) rendered under /favorites (PrivateRoute).

URL query string state management
Source of truth: q, ownerId, sort, page, pageSize in query string.

On mount: parse and coerce invalid values; optionally replace URL with normalized params.

On search/filter/sort: reset page=1; update URL; refetch.

Pagination controls update page in URL only; disable based on meta boundaries.

Debounce strategy
Submit-driven search to match acceptance criteria.

Optional enhancement: debounce live search at 400ms (not required by AC).

US-001
Acceptance Criteria

Design Elements

Search updates list by title/description (case-insensitive)

API: GET /api/courses?q= with LOWER()+LIKE; Frontend: CatalogToolbar submit; LLD: Sequelize where OR.

Clear search shows full list

Frontend: Clear removes q and resets page=1; API: no q => unfiltered.

Next page updates URL and results

Frontend: PaginationControls increments page in URL; API: limit/offset; Response meta.

Prev/Next disabled at bounds

Frontend: disable based on meta.page and meta.totalPages.

Invalid page coerced to 1

API: coercion; Frontend: normalize query params.

No matches shows empty state

Frontend: EmptyState when items.length==0; Wireframe.

US-002
Acceptance Criteria

Design Elements

Filter by owner

API: ownerId filter on Course.userId; Frontend: owner dropdown + URL.

Change sort reloads filtered results

Frontend: keep ownerId/q, reset page=1; API applies where+order.

Title (A-Z)

API: sort=title_asc order by title ASC.

Newest

API: sort=newest order by createdAt DESC.

Invalid sort defaults to Newest

API: allowlist validation; meta.sortApplied.

URL preserves filter/sort

Frontend: query string as source of truth; HLD state persistence.

Acceptance Criteria

Design Elements

Acceptance Criteria

Design Elements

Favorite toggle shows current state when signed in

Frontend: FavoriteToggle; API: isFavorited in GET course detail (optional) or secondary call; DB: Favorites join table.

Toggle ON favorites without refresh

API: POST /api/courses/:id/favorite; Frontend: optimistic update; DB unique constraint.

Toggle OFF unfavorites

API: DELETE /api/courses/:id/favorite; Frontend: optimistic update.

My Favorites shows only my items

Route: /favorites (PrivateRoute) + MyFavorites; API: GET /api/users/me/favorites.

Unauthenticated favorite redirects to sign-in

Frontend: navigate('/signin'); API enforces 401 if attempted.

Deleting course removes favorites

DB: FK cascade delete on Favorites.courseId; existing DELETE course triggers cascade.
